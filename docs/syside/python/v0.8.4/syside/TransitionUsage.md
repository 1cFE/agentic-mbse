# TransitionUsage <span class="sd-sphinx-override sd-badge sd-outline-primary sd-text-primary">SysML</span><a href="#transitionusage-sysml" class="headerlink" title="Link to this heading"><span class="nerd-font"></span></a>

*<span class="pre">class</span><span class="w"> </span>*<span class="sig-name descname"><span class="pre">TransitionUsage</span></span><a href="#syside.TransitionUsage" class="headerlink" title="Link to this definition"><span class="nerd-font"></span></a>  
Implementation of <span class="pre">`TransitionUsage`</span> defined in the SysML specification.

**Specification**:

> <div>
>
> A <span class="pre">`TransitionUsage`</span> is an <span class="pre">`ActionUsage`</span> representing a triggered transition between <span class="pre">`ActionUsages`</span> or <span class="pre">`StateUsages`</span>. When triggered by a <span class="pre">`trigger_action`</span>, when its <span class="pre">`guard_expression`</span> is true, the <span class="pre">`TransitionUsage`</span> asserts that its <span class="pre">`source`</span> is exited, then its <span class="pre">`effect_action`</span> (if any) is performed, and then its <span class="pre">`target`</span> is entered.
>
> A <span class="pre">`TransitionUsage`</span> can be related to some of its <span class="pre">`owned_features`</span> using <span class="pre">`TransitionFeatureMembership`</span> <span class="pre">`Relationships`</span>, corresponding to the <span class="pre">`trigger_action`</span>, <span class="pre">`guard_expression`</span> and <span class="pre">`effect_action`</span> of the <span class="pre">`TransitionUsage`</span>.
>
> </div>

For language description, see section <a href="https://raw.githubusercontent.com/Systems-Modeling/SysML-v2-Release/refs/tags/2025-07/doc/2a-OMG_Systems_Modeling_Language.pdf#page=150" class="reference external" target="_blank">7.18.3</a> of the SysML specification.
