# Codex adapter

Invoke modeling workflows as `$spec-model`, `$orchestrate-modeling`, or the other installed skill names. Slash-prefixed workflow references in shared prose mean the corresponding Codex skill, not a built-in slash command. Load the referenced `.agents/skills/<name>/SKILL.md` explicitly when needed. Claude-specific frontmatter such as allowed-tools and user-invocable does not configure Codex permissions or catalog visibility.

Use available shell/search/patch tools for file operations, native web search/open tools for research, and image viewing tools for rendered images. For owner questions use the host’s question interface when available in the current mode, otherwise ask in text. Preserve explicit conversational questions and wait for required answers. Reading a skill is the native equivalent of Claude’s Skill tool; do not invent a Skill API call.

Use the exposed delegation interface and installed expert role names. Map exploration to the host’s explorer role and general stage work to its default role. Keep a continuing author across stages and clarifications while its context remains useful. Independent criticism requires a fresh non-author agent with only its self-contained brief. If the tool exposes fork_turns, set it to "none" for that reviewer; do not resume an author for its audit. Native CLI tool schemas can differ: inspect the exposed schema rather than passing unsupported arguments. Spawn independent work together when permitted, gather final results, and release finished agents when the host exposes that operation. Nested stages may delegate experts; queue work within host limits. If required delegation is unavailable, return a blocker rather than substituting self-review.

Project custom roles require the repository to be trusted in Codex. If a role is unknown, check project trust and configuration loading before changing the role definition. Expert TOML definitions live in `.codex/agents/` and are registered in `.codex/config.toml` for clients that require explicit role registration. The three reference readers use a read-only filesystem sandbox; this does not remove shell or web capabilities. Other roles inherit the host’s active policy. The installer appends missing MBSE role registrations to `.codex/config.toml`, preserving existing values, roles, and comments. It does not broaden sandbox permissions. For an external reference, try the required read; if blocked, use the host’s approval mechanism for that read. Do not grant writable roots to satisfy read access. MCP requires native server setup and discovery of actual tool names. Formatting is explicit unless the owner separately configures a native hook; Claude hook payloads are not interchangeable.
