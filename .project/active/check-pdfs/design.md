## Overview

Bundle a small set of purpose-built test PDFs inside the package so `agentic-mbse extract --check` works with no arguments. Run probes against each PDF and aggregate results: a probe is PASS if it passed on any PDF in the corpus.

## Research Findings

### Current `run_check()` flow (check.py:460-547)

1. `extract_pages(pdf_path)` — pymupdf4llm extraction (all pages)
2. `select_pages(pages)` — picks best headings/math/tables pages via heuristics
3. Runs 6 probes sequentially: pymupdf, gmft, img2table, docling, pandoc, claude
4. `compute_capabilities()` + `compute_overall()` → `CheckResult`

Key: GMFT and Img2Table run on the *entire* PDF (not just selected pages). Model loading is the bottleneck (~8-15s for GMFT, ~5-10s for Img2Table), but once loaded, processing additional pages is fast. A 1-2 page arXiv PDF adds negligible overhead.

### CLI `--check` path (extract_cli.py:230-263)

- Requires a positional `path` argument (currently mandatory)
- Rejects directories with multiple PDFs: `if len(docs) > 1: error`
- Maps `CheckResult.overall` to exit codes: PASS→0, DEGRADED→1, FAIL→2

### arXiv detection (pandoc_convert.py:69-101)

`detect_arxiv_id()` reads page 1 text via pymupdf, applies regex `arXiv:(\d{4}\.\d{4,5}(?:v\d+)?)`. Falls back to PDF Creator metadata. The arXiv PDF must have this string on page 1 for detection to work.

### Package data (pyproject.toml:48-56)

The wheel is configured with `packages = ["src/agentic_mbse"]` — anything under `src/agentic_mbse/` is automatically included. No `force-include` entry needed for files placed there.

### Existing corpus

`tests/corpus/pdfs/paischer_2025.pdf` (1.4MB, 24 pages) is the only arXiv paper in the corpus (`arxiv_id: 2510.07314v1`). Too large for bundling whole, but page 1 contains the arXiv ID and can be extracted as a 1-page subset.

### Key patterns

- Data path resolution: `_get_data_root()` in `cli/__init__.py:107-127` handles dev vs pip-installed paths
- For check.py, simpler: `Path(__file__).parent / "check_corpus"` resolves to `src/agentic_mbse/extraction/check_corpus/` in both modes since check.py is inside the package

## Proposed Design

### Component 1: Test PDF Corpus

**Location:** `src/agentic_mbse/extraction/check_corpus/`

Two PDFs, both extracted from real papers in `tests/corpus/pdfs/`:

**`test_features.pdf` (PDF A, ~200-400KB)** — 3-5 pages extracted from `sparc_overview.pdf` (tables + math, 25 pages, 1.9MB):
- Run `select_pages()` against the full PDF to find the best headings/math/tables pages
- Extract those pages (plus page 0 for headings if not already selected) via `doc.select()`
- Guarantees real content that triggers `_assess_math_garbling()` and `count_pipe_rows()` — no synthetic content needed

Source: `sparc_overview.pdf` — 25 pages, has both tables and math per `papers.jsonl`.

**`arxiv_probe.pdf` (PDF B, ~50-100KB)** — Page 1 extracted from `paischer_2025.pdf`:
- Contains `arXiv:2510.07314v1` on page 1 (exercises arXiv detection)
- HTML available on ar5iv (exercises full Pandoc conversion path)
- Created via `doc.select([0])` → single-page PDF

Both generated by `scripts/generate_check_pdf.py` (pymupdf page extraction, not synthesis) and checked into the repo.

### Component 2: Corpus Discovery Function

**File:** `src/agentic_mbse/extraction/check.py`

```python
def get_check_corpus() -> list[Path]:
    """Return paths to built-in test PDFs for --check."""
    corpus_dir = Path(__file__).parent / "check_corpus"
    if not corpus_dir.exists():
        return []
    return sorted(p for p in corpus_dir.iterdir() if p.suffix == ".pdf")
```

### Component 3: Result Aggregation

**File:** `src/agentic_mbse/extraction/check.py`

New function to merge multiple `CheckResult` objects:

```python
# Status priority for aggregation: higher = better
_STATUS_PRIORITY = {
    ProbeStatus.PASS: 5,
    ProbeStatus.UNTESTED: 4,
    ProbeStatus.SKIPPED: 3,
    ProbeStatus.NOT_INSTALLED: 2,
    ProbeStatus.FAIL: 1,
}


def merge_check_results(results: list[CheckResult]) -> CheckResult:
    """Aggregate probe results across multiple PDFs.

    For each probe component, keeps the best status (PASS > UNTESTED > ... > FAIL).
    Uses the detail string from whichever PDF produced the best status.
    """
```

Logic:
1. Group probes by `component` name across all results
2. For each component, pick the `ProbeResult` with highest `_STATUS_PRIORITY`
3. Merge `SelectedPages`: take the first non-None value for each field (headings, math, tables)
4. Sum `total_pages` across all results
5. Recompute `capabilities` and `overall` from merged probes
6. Set `pdf_name` to `"built-in corpus (N PDFs)"` or similar

For the Claude probe specifically: only run it on the first PDF (subsequent PDFs pass `claude_budget=0` to `run_check()`). This avoids double-spending — the Claude probe tests "does the CLI work?", which is environment-level.

### Component 4: CLI Changes

**File:** `src/agentic_mbse/cli/extract_cli.py`

**Argparse change:** Make `path` optional for `--check`:

```python
p.add_argument(

```

**Handler change** in `cmd_extract()`:

```python
if args.check:
    if args.path is None:
        # Built-in corpus mode
        from agentic_mbse.extraction.check import get_check_corpus, merge_check_results
        corpus = get_check_corpus()
        if not corpus:
            print("Error: built-in test corpus not found")
            return EXIT_FAILURE

        results = []
        for i, pdf in enumerate(corpus):
            # Only spend Claude budget on first PDF
            budget = args.budget if i == 0 else 0
            results.append(run_check(pdf, claude_model=args.model, claude_budget=budget))

        check_result = merge_check_results(results)
    else:
        # User-provided PDF — current behavior
        path = Path(args.path)
        ...  # existing single-PDF logic
else:
    if args.path is None:
        print("Error: path is required (unless using --check)")
        return EXIT_FAILURE
    ...  # existing extraction logic
```

Remove the `len(docs) > 1` rejection for built-in corpus mode (it only applies when the user provides a path).

### Component 5: Output Formatting

No changes to `format_check_json()` or `print_check_table()` — they already work with `CheckResult`. The merged result will have `pdf_name="built-in corpus (2 PDFs)"` which communicates that the built-in corpus was used.

For the built-in corpus run, add a brief note to stderr before probing starts:
```
Using built-in test corpus (2 PDFs)
```

### Component 6: Generation Script

**File:** `scripts/generate_check_pdf.py`

Dev-only script (not installed with package). Extracts pages from real corpus PDFs:

1. `generate_test_features()` — Extracts best pages from `sparc_overview.pdf`:
   - `extract_pages()` → `select_pages()` to find headings/math/tables pages
   - `doc.select([0, math_page, tables_page, ...])` → keeps only relevant pages
   - Validates: `select_pages()` on the output PDF still finds math + tables
   - Saves to `src/agentic_mbse/extraction/check_corpus/test_features.pdf`

2. `extract_arxiv_probe()` — Extracts page 1 from `paischer_2025.pdf`:
   - `doc.select([0])` → single-page PDF
   - Validates: `detect_arxiv_id()` on the output PDF returns `2510.07314v1`
   - Saves to `src/agentic_mbse/extraction/check_corpus/arxiv_probe.pdf`

Run once: `uv run python scripts/generate_check_pdf.py`

## Potential Risks

1. **arXiv HTML availability changes.** If `2510.07314v1` loses HTML on ar5iv, the pandoc probe will report "no HTML available" instead of testing the full conversion path. Mitigation: the probe still passes (PASS with "no HTML available" detail) — it's a degraded test, not a failure. Can update the arXiv PDF later if needed.

2. **Extracted pages lose math/table content.** Unlikely since we're extracting from papers known to have these features, and the generation script validates `select_pages()` on the output. If validation fails, the script errors and we pick different source pages.

3. **Package size.** Two small PDFs (50-200KB each) are well under the 1MB budget. Risk is low.

## Integration Strategy

This change is additive — it adds a new code path (built-in corpus) alongside the existing user-provided PDF path. The only breaking change is making the `path` argument optional in argparse, which is backward compatible (existing `--check my.pdf` invocations still work).

Files modified:
- `src/agentic_mbse/extraction/check.py` — add `get_check_corpus()`, `merge_check_results()`
- `src/agentic_mbse/cli/extract_cli.py` — optional `path`, built-in corpus branch
- `pyproject.toml` — no changes needed

Files created:
- `src/agentic_mbse/extraction/check_corpus/test_features.pdf`
- `src/agentic_mbse/extraction/check_corpus/arxiv_probe.pdf`
- `src/agentic_mbse/extraction/check_corpus/__init__.py` (empty, for package discovery)
- `scripts/generate_check_pdf.py`

## Validation Approach

### Unit tests (in `tests/test_check.py`)

1. **`TestGetCheckCorpus`**: Verify `get_check_corpus()` returns PDFs from the corpus directory
2. **`TestMergeCheckResults`**:
   - PASS on any PDF → merged PASS
   - All FAIL → merged FAIL
   - Mix of PASS and UNTESTED → PASS wins
   - Claude cost_usd preserved from first PDF
   - SelectedPages merged (first non-None wins)
3. **`TestCliBuiltinCorpus`**: Mock `run_check` + `merge_check_results`, verify CLI calls them when path is None

### Integration test

- `uv run agentic-mbse extract --check` with no args → should complete without error
- Verify all 6 probes report non-UNTESTED status

- Run `uv run agentic-mbse extract --check` and inspect output
