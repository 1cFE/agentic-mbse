## Business Goals

### Why This Matters

The `pdf-analysis` skill ships a 3-tier extraction pipeline (pymupdf4llm → Docling MCP → image fallback), but only Tier 1 and Tier 3 work out of the box. Tier 2 requires a Docling MCP server that must be installed, configured with system-appropriate resource limits, and registered with Claude Code. Without this, users get a skill that references `mcp__docling__*` tools that don't exist, leading to failed workflows and confusion.

Additionally, the skill prompt itself is static — it always describes all three tiers regardless of what the system can handle. A constrained 8GB machine should get different guidance than a 32GB workstation.

### Success Criteria

- [ ] `agentic-mbse init` sets up the Docling MCP server by default (opt-out with `--no-docling`)
- [ ] System resources are detected and classified into tiers (constrained/moderate/comfortable)
- [ ] The wrapper script and MCP registration are tier-appropriate
- [ ] The skill prompt adapts to the detected tier
- [ ] Users who opt out get a working 2-tier skill (Tier 1 + Tier 3 only)
- [ ] Re-running init does not duplicate the MCP registration
- [ ] `scripts/replicate_setup.sh` stays coordinated

### Priority

High — the pdf-analysis skill is already in `MBSE_SKILLS` and deploys on init, but Tier 2 is broken without this work.

## Problem Statement

### Current State

- The `pdf-analysis` skill directory deploys correctly (already in `MBSE_SKILLS`, copied/symlinked by init)
- The Docling MCP server was manually configured: wrapper script at `~/.local/bin/docling-mcp-wrapper.sh`, registered via `claude mcp add --scope user`
- The setup script exists at `.project/active/pdf-skill/setup-docling.sh` but is not integrated into init
- The SKILL.md is static — always describes all 3 tiers regardless of system capability
- `pymupdf4llm` is an optional dep (`[extract]`) but init doesn't check for it

### Desired Outcome

Running `agentic-mbse init` automatically:
1. Detects system resources (RAM, GPU, cores)
2. Classifies into a tier
3. Creates a tuned wrapper script
4. Tests the MCP server launch
5. Registers with Claude Code at user scope
6. Generates an environment report
7. Installs a tier-adapted version of the skill prompt

Users who can't or don't want Docling can pass `--no-docling` and get a clean 2-tier skill.

## Scope

### In Scope

- **Docling MCP setup during init**: Bundle `setup-docling.sh` and call it as a subprocess from `cmd_init()`
- **`--no-docling` flag**: Opt-out flag on `agentic-mbse init` to skip Docling setup entirely
- **Tier detection**: Reuse the existing script's environment detection (RAM, GPU, cores → constrained/moderate/comfortable)
- **Adaptive SKILL.md**: Generate the skill prompt with tier-specific content during init
- **Environment report**: `~/.docling-mcp-env.md` generated by the setup script
- **Re-init safety**: Detect existing Docling MCP registration and update rather than duplicate
- **`replicate_setup.sh` coordination**: Mirror the Docling setup call for dev mode
- **pymupdf4llm guidance**: Print a message if `pymupdf4llm` is not installed (Tier 1 + 3 need it)

### Out of Scope

- Changes to `agentic-mbse extract` CLI command
- Docling as a hard Python dependency (stays as MCP server via `uvx`)
- GPU-specific optimizations beyond the existing tier logic (future feature)
- Changes to the extraction backends in `src/agentic_mbse/extraction/`

### Edge Cases & Considerations

- **First-run model download**: Docling downloads ~500MB of models on first use. The setup script's launch test triggers this. Init should warn the user about the wait.
- **Launch test timeout**: The setup script waits 30s + 120s timeout for the server to start. On slow systems or first runs, this may take a while. Init output should indicate progress.
- **Wrapper already exists**: Re-init should overwrite the wrapper (it's tool-owned, not user-owned) but preserve the MCP registration if already connected.
- **`claude` CLI not available**: If `claude mcp add` can't run (e.g., claude CLI not in PATH), the setup should warn but not fail init entirely. The skill still works at Tier 1 + 3 without MCP.
- **Cross-platform**: The setup script uses `/proc/meminfo` (Linux-specific). macOS support would need `sysctl` — flag as a known limitation for now.

## Requirements

### Functional Requirements

> Requirements below are from user's request unless marked [INFERRED].

1. **FR-1**: `agentic-mbse init` MUST run Docling MCP setup by default
2. **FR-2**: `agentic-mbse init --no-docling` MUST skip Docling setup entirely
3. **FR-3**: The setup MUST detect system resources and classify into tiers (constrained ≤8GB / moderate 9-16GB / comfortable 17GB+)
4. **FR-4**: The setup MUST create a wrapper script at `~/.local/bin/docling-mcp-wrapper.sh` with tier-appropriate thread limits and environment variables
5. **FR-5**: The setup MUST register the Docling MCP server with Claude Code at user scope (`claude mcp add --scope user`)
6. **FR-6**: The setup MUST generate an environment report at `~/.docling-mcp-env.md`
7. **FR-7**: The SKILL.md installed by init MUST adapt to the detected tier — specifically whether Tier 2 (Docling) guidance is included and what page-count limits are recommended
8. **FR-8**: When `--no-docling` is used, the installed SKILL.md MUST describe only Tier 1 + Tier 3 (no Docling MCP references)
9. **FR-9**: [INFERRED] Re-running init MUST NOT create duplicate MCP registrations (detect existing, update or skip)
10. **FR-10**: [INFERRED] `scripts/replicate_setup.sh` MUST be updated to call the setup script in dev mode
11. **FR-11**: [INFERRED] The setup script MUST be bundled as a resource (alongside skills/agents/hooks) so it's available in pip-installed packages

### Non-Functional Requirements

- The Docling MCP launch test SHOULD complete within 120 seconds
- If the launch test fails due to OOM, the setup SHOULD fall back to a no-docling configuration and warn the user rather than failing init
- Init output SHOULD clearly indicate Docling setup progress (it's the slowest step)

## Acceptance Criteria

### Core Functionality

- [ ] `agentic-mbse init` on a fresh project sets up Docling MCP and installs tier-adapted SKILL.md
- [ ] `agentic-mbse init --no-docling` skips Docling setup and installs 2-tier SKILL.md
- [ ] Wrapper script is created with correct tier-specific thread limits
- [ ] `claude mcp list` shows `docling: connected` after init
- [ ] Environment report at `~/.docling-mcp-env.md` contains correct system info and tier
- [ ] Re-running init does not create duplicate MCP registrations
- [ ] SKILL.md content varies based on tier (constrained gets single-page-only guidance, comfortable gets batch guidance)
- [ ] SKILL.md with `--no-docling` contains no `mcp__docling__` references

### Quality & Integration

- [ ] Existing tests continue to pass
- [ ] `scripts/replicate_setup.sh` mirrors the Docling setup for dev mode
- [ ] The setup script is included in the wheel build (`pyproject.toml` force-include)
