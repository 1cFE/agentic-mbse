## Phase 2: Manual Inspection

For each document, open both the source PDF and the extracted `full_document.md` + `INDEX.md` side by side. Evaluate the following dimensions.

### 2a. Structure & Headers

For each document:

- [ ] Are section headings correctly identified with `##`/`###` markdown headers?
- [ ] Does `INDEX.md` reflect the real structure of the document?
- [ ] Count: correct headers, false positive headers (noise promoted), false negative headers (real headers missed)

**Document-specific checks:**

| Document | Key Question |
|----------|-------------|
| 2243 (slides, 127p) | Does the pipeline produce ANY useful structure? Slides have bold titles but no numbered sections. Does `promote_bold_headers` fire? Does `promote_plain_headers` fire? Or is the output a 127-page wall of text? |
| 2244 (arXiv) | Are standard LaTeX `\section{}` headings correctly detected? Are subsections at the right depth? |
| Fusion Safety (slides) | Same as 2243 — are slide titles detected? |
| fusion-standards (2-col) | Are the two columns extracted sequentially or interleaved? Are section headings from the magazine layout detected? |
| hazards-afify (Word) | Are Word-formatted headings (which use different font/style conventions than LaTeX) detected? |

### 2b. Table Quality

For each document that contains tables in the source PDF:

- [ ] Identify all tables in the source PDF (manual count)
- [ ] For 2-3 tables per document, compare against the extracted output:
  - Column headers correct?
  - Row count correct?
  - Numerical values match the PDF?
  - Any row merging, duplication, or garbling?
  - Was the table extracted as pipe format, plain text, or missed entirely?

**Document-specific checks:**

| Document | Key Question |
|----------|-------------|
| 2244 (arXiv) | LaTeX tables with visible rules — this is GMFT's training data sweet spot. Does it perform well? |
| hazards-afify (Word) | Word tables use different border/spacing conventions. Does GMFT detect them? |
| Fusion Safety (slides) | Slides may have data tables in unusual formats. Are they handled at all? |

| **Running header stripping** (threshold=3, strips short repeated lines) | Was any legitimate content removed? Check for missing bullet points, repeated terms, etc. | 2243 (127 pages — repeated slide footer/header text is likely, but what about repeated short content lines?) |

### 3.2 Per-document assessments

#### 2243 — Rider, "Is There a Better Route to Fusion" (127-page PowerPoint slides)

**Structure: F.** Zero slide titles promoted to headers. The pipeline requires numbered section patterns (`1 Introduction`, `2.1 Background`), but slide titles are unnumbered bold text (`**Motivation**`, `**Wish List of Characteristics**`). Instead, 68 false-positive headers were created from equation fragments and physics notation that matched the appendix regex `[A-Z](\.\d+)* `:

- `## A ≥ 15` (binding energy chart label — appears 6 times)
- `## D µ or T µ` (diagram label — 3 times)
- `## 200 fusions x 17.6 MeV x 1/3 effic.` (calculation fragment — 2 times)
- `## 1 10** **100` (graph axis labels)
- `## N << Z` / `## N >> Z` / `## N ~ Z` (nuclear notation — 3 each)

The appendix regex is the primary offender: it promotes any bold line starting with a single capital letter followed by a space, which in a physics presentation matches variable names (A, D, N) constantly.

**INDEX: Actively harmful.** 52 entries, all garbage. No actual slide title appears in the index. A user trying to navigate would be worse off than with no index at all.

**Content: B for text slides, F for equations.** Bullet lists are well preserved (e.g., "Wish List of Characteristics" has clean nested bullets). But math-heavy slides are shattered — equations have each symbol on its own line, making them unreadable. Example: `E` / `**e** **[2]**` / `**~**` / `14.4 eV` was originally `E_chem ~ 14.4 eV`.

**Ligatures: Properly repaired.** The PowerPoint source has Unicode ligatures (U+FB01 fi, U+FB02 fl), and `repair_ligatures()` correctly decomposed them. Words like "efficient", "confinement" read correctly.

**Tables: Mixed.** ~20 pipe tables were extracted. Some are real data tables from comparison slides (fusion reaction parameters, 9 columns, 20 rows — good data). Others are false tables — GMFT interpreted chart axes and diagram grids as tabular data, producing empty or garbage pipe tables.

**Build slides:** The source has extensive "build" animations (progressive reveal), so the same content appears 3-9 times across consecutive slides. This is inherent to the source, not a pipeline bug, but inflates the document substantially.

**Grade: D** — The text is there but the structural failure makes the output nearly unusable for navigation. The false-positive headers actively mislead.

#### 2244 — Swanson et al., "Helios Stellarator" (29-page arXiv paper)

**Structure: Partial.** Top-level `\section` headings (6 total) were correctly detected as `## ` headers — `## 1. Introduction`, `## 2. Summary of the design`, `## 3. Plasma design and simulation`, `## 4. Engineering design of systems`, `## 5. Conclusion`, `## 6. Acknowledgments`. All correct depth and numbering.

However, all 15 `\subsection` / `\subsubsection` headings were **completely missed**. They render as italic text in the PDF, and pymupdf4llm extracts them as `_3.1. Title_` (italic markdown). The postprocessor has no pattern for italic-wrapped numbered headers — `promote_bold_headers()` only matches `**bold**`, and `promote_plain_headers()` requires no markdown formatting. Examples of missed subsections:

- `_3.1. Scoping studies, heating and fueling, and dynamic_` (should be `### 3.1 ...`)
- `_3.2. The stellarator equilibrium_` (should be `### 3.2 ...`)
- `_4.1. Electromagnetic coil engineering_` (should be `### 4.1 ...`)
- `_3.4.1. A note on the e_ ff _ects of an abrupt plasma termi-_` (broken by ligature mid-word)

**INDEX: Effectively empty.** Reports `section_count: 0` despite the document having 21 real sections/subsections. Only the document title appears.

**Tables: Good.** Table 1 (Helios design parameters) extracted as a clean 18-row, 3-column pipe table. Column headers correct. Values correct. Minor ligature issues in cells: `Magnetic feld` (missing 'i'), `confnement` (missing 'i'), `efciency` (missing 'ffi'). These are in-cell ligature failures that `repair_ligatures()` didn't catch — the ligatures appear as missing characters rather than as Unicode codepoints.

**Figures: Excellent.** 13 images extracted, 12 of 12 named figures have captions promoted into alt-text via `promote_figure_captions()`. Multi-panel figures handled correctly.

**Math: Fair.** Greek letters preserved as Unicode (β, ι, τ, γ, ω, κ). Subscripts/superscripts inconsistent: sometimes `_subscript_` (italic), sometimes `~~superscript~~` (strikethrough), sometimes `[superscript]` (brackets). Garbled integral expression at line 570: `(∫ _dA_ ( _B_ [→] - _n_ ˆ) [2] )`.

**NEW FAILURE MODE: Italic subsection headers.** This is a format the pipeline has never seen. The original corpus used bold headers exclusively. This arXiv paper uses italic styling for subsections (common in some LaTeX document classes), and the pipeline is completely blind to it.

**Grade: C+** — Top-level structure works, tables and figures are good, but the 15 missing subsections make the document appear flat and unstructured. The INDEX is useless.

#### fusion-standards (4-page IAEA magazine article, ABBYY FineReader OCR)

**Structure: Broken.** One `## ` header detected: `## 24 IAEA BULLETIN, 4/1995` — this is a **page footer** falsely promoted to a section header. The "24" is a page number that matched the numbered section pattern. Meanwhile, all 6 real section headings (`**Safety-related goals and considerations**`, `**Practical realization of fusion**`, `**IAEA activities in fusion safety**`, `**Prospects and future directions**`, `**Fusion Safety Analysis**`) remain as bold text, undetected — they have no section numbers.

**INDEX: Actively misleading.** Contains one entry pointing to the falsely promoted page footer.

**Two-column layout: Partially interleaved.** Page 1 shows column mixing: the author byline (`**Franz-Nikolaus**` / `**Flakus, John C.**`) is scattered across the body text, with `**Cleveland, and**` / `**T. J. Dolan**` appearing 40 lines later. Pages 2-3 read much better — columns extracted sequentially.

**OCR artifacts:** `andeconomics` (missing space), `I or some decades` (decorative capital "F" misread as "I" by ABBYY FineReader). Page 4 is severely garbled: structured hazard lists rendered as `< **t** toxic materials, such` / `<` / `(ft vacuum` / `<» cryogenic fluids`. Near-unreadable.

**Duplicate content:** Pages 3-4 have text blocks that appear twice, likely from overlapping text boxes in the magazine layout.

**Running headers: NOT stripped despite appearing 4 times.** The footer `IAEA BULLETIN, 4/1995` appears on every page. It should be stripped (threshold=3, appears 4 times). **Bug confirmed:** the footer appears on the same line or immediately after `<!-- PAGE:N -->`, forming a single two-line block. The `strip_running_headers()` function skips multi-line blocks (`"\n" in stripped`), so the page marker prevents detection.

**Grade: D+** — Body text on pages 2-3 is usable. Page 1 column interleaving and page 4 OCR garbling are significant problems. The INDEX is misleading. The false-positive footer-as-header is a concrete heuristic failure.

**Structure: Missing.** Zero headers detected. All 13 section headings are unnumbered bold text: `**Introduction to Fusion Hazards**`, `**Development of a Fit for Purpose Safety Case Approach**`, `**STEP Safety Philosophies**`, `**Top Level Safety Functional Requirements**`, `**Design Safety Principles**`, `**Fusion Safety Case Pillars**`, etc. None have section numbers, so none are promoted.

Numbered lists with sub-items (`1.`, `a.`, `b.`, `c.`) properly formatted. Nested bullet lists with `  -` indentation correct throughout.

**Figures:** 3 images extracted (1 page graphic + 2 figure images). Figure captions appear *before* their images rather than after, so `promote_figure_captions()` didn't fire (it expects caption after image).

**Minor artifacts:** Lost hyphens at line breaks: `decisionmaking` (should be `decision-making`), `fissionbased` (should be `fission-based`).

**Grade: B-** — Body text quality is the best in the new corpus. Lists, references, citations all excellent. But zero structural detection and un-stripped running headers are significant usability problems.

## Phase 4: Decision

### 4.1 Are there regressions or new failure modes?

**Yes — significant new failure modes.** The pipeline was designed for and tuned against numbered-section academic papers. On the 5 new documents:

- **0/5 documents have a usable INDEX** (vs 5/7 in original corpus)
- **4/5 documents have zero correct headers** (vs ~5/7 correct in original)
- A new failure mode (italic subsection headers) was discovered that would affect many arXiv papers
- The appendix regex produces catastrophic false positives on physics/engineering content with single-letter variables
- Running header stripping has a concrete bug that went unnoticed in the original corpus

These are not edge cases — they represent common document types (slide decks, conference papers, magazine articles, arXiv papers with italic subsections).

### 4.2 Do any fragility points trigger?

**Yes — 5 of 7 checked fragilities triggered or partially triggered:**

1. Non-numbered sections missed → CRITICAL, 4/5 docs
2. Running header stripping bug → MEDIUM, 2/5 docs
3. Appendix regex false positives → HIGH, 1/5 docs
4. Footer-as-header false positive → MEDIUM, 1/5 docs
5. Ligature repair incomplete → LOW, 1/5 docs

### 4.3 Is the pipeline's scope well-defined?

**The pipeline works well for:**
- Born-digital, single-column English technical reports and papers with **bold numbered section headings** (e.g., `**1 Introduction**`, `**2.1 Background**`)
- Documents where pymupdf4llm's `hdr_info` callback fires correctly (bold + digit prefix)

**The pipeline has known limitations for:**
- **Slide decks / presentations** (no numbered sections → no structure detected, appendix regex creates garbage headers on physics content)
- **Conference papers without numbered sections** (Word-origin, proceedings-style → text is excellent but no structure)
- **arXiv papers with italic subsection headings** (top-level sections detected, all subsections missed)
- **Two-column magazine layouts** (partial column interleaving, OCR artifacts amplified)
- **Scanned / OCR'd documents** (pre-existing OCR quality issues, not a pipeline problem per se)

### 4.4 PR readiness verdict

**The body text extraction is solid across all document types.** Lists, references, citations, page markers, image extraction, ligature repair — all work well. The raw extraction quality is genuinely good.

**The structural detection (headers, INDEX) is the problem.** It works well within its designed scope (numbered-section papers) but fails silently outside it, and the failure can be actively harmful (garbage headers, misleading INDEX entries).

**Recommendation: Ship with scope documentation, fix the two concrete bugs.**

Two issues are clearly bugs that should be fixed before PR regardless:

1. **PAGE marker blocking running header removal** — the `<!-- PAGE:N -->` line should be split into its own block before running header detection, or the running header check should handle multi-line blocks that start with an HTML comment. This is a straightforward fix.

2. **Appendix regex false positives** — `[A-Z](\.\d+)* ` is too greedy. At minimum, require the entire line to be bold (not just the first letter) and require the title portion after the letter to start with an uppercase word (not a symbol like `≥`, `µ`, `<<`). Example tightening: `^\*\*([A-Z](?:\.\d+)*)\s+([A-Z][a-z].+?)\*\*\s*$`.

The unnumbered-headers gap (failure mode #1) and italic-headers gap (#2) are larger design decisions that could be deferred to v2.1, but the scope should be documented clearly in the PR description and CLI `--help` text.

**Suggested scope statement for the PR:**

> PDF extraction v2 is optimized for English-language technical reports and academic papers with numbered section headings. Documents without numbered sections (slide decks, conference proceedings, magazine articles) will have body text extracted correctly but section structure and INDEX generation may be incomplete. Italic-formatted subsection headings (common in some LaTeX document classes) are not currently detected.
