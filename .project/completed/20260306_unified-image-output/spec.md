## Business Goals

### Why This Matters

The v4 pipeline currently produces zero images in its output. Embedded figures are silently dropped (`write_images=False` in `extract_pages()`), and table crop PNGs generated by GMFT/Img2Table during detection are saved to temporary directories and discarded after Claude enhancement. For techno-economic analysis papers, figures (cost breakdowns, sensitivity charts, comparison plots) and table crops are critical domain knowledge that an LLM reading the extracted document cannot access.

The old pipeline (`extract()` in `pymupdf_backend.py`) preserved figures with `write_images=True` and produced 8 inline `![](images/...)` references for the TEA document. The v4 pipeline produces 0. Meanwhile, table crops — which the old pipeline never had — are generated but thrown away.

Building separate image plumbing for figures, table crops, and future equation crops would mean touching `pipeline.py`, `_postprocess_final()`, and `PipelineResult` three times with slightly different wiring each time. A unified image collector handles all sources through one mechanism.

### Success Criteria

- [x] Embedded figures saved to `images/` with inline `![](images/...)` references in output
- [x] Table crop PNGs from GMFT/Img2Table saved alongside figures in `images/`
- [x] Table crops referenced in markdown near their pipe tables
- [x] Figure captions promoted from separate paragraphs to image alt-text
- [x] Image paths are relative in final output (not absolute pymupdf paths)
- [x] `PipelineResult.image_count` reflects total images persisted
- [x] No images saved when `extracted_images_dir` is None (backward compatibility)
- [x] Orphan figure files from Claude-replaced pages are acceptable and silent

### Priority

P1 — second item in EPIC-PDFV4-002. Dependency on Item 1 (quality regressions Phases 1-3) is satisfied (completed 2026-03-01). Blocks Item 3 (equation region detection) which needs the collector infrastructure.

## Problem Statement

### Current State

The v4 pipeline has no image output of any kind:

1. **Figures dropped**: `extract_pages()` calls pymupdf4llm with `write_images=False`. Figure images are never extracted, never saved, and no references appear in the markdown. On Claude-replaced pages, Claude produces text placeholders like `[Figure 5: caption]`. On KEEP and GMFT pages, figures are silently gone.

2. **Table crops discarded**: GMFT and Img2Table save cropped table images to `tempfile.mkdtemp()` directories during detection. These paths are stored in `DetectedTable.image_path` and passed to Claude for table enhancement. After enhancement, the temp files are abandoned — never copied to a persistent location.

3. **No image output directory**: The pipeline creates no `images/` directory. The old `extract()` function created one; the v4 `extract_pdf()` does not.

4. **No path normalization**: pymupdf4llm writes absolute paths (`![](/absolute/path/to/images/doc-0-0.png)`). The old pipeline called `normalize_image_paths()` to convert these to relative `images/` paths. The v4 `_postprocess_final()` does not call this function.

### Desired Outcome

A single `ImageCollector` accumulator travels through the pipeline, gathering images from all sources. At the end of the pipeline, it copies all images to `output_dir/images/` and normalizes paths in the final markdown. Future image sources (equation crops from Item 3) plug into the collector with zero plumbing changes.

## Scope

### In Scope

- ImageCollector + ImageEntry dataclasses for accumulating images from multiple sources
- Figure extraction via `write_images=True` in `extract_pages()` when images dir is provided
- Table crop persistence from `DetectedTable.image_path` temp files into the collector
- `PipelineConfig.extracted_images_dir` field and CLI wiring to create `output_dir/images/`
- `_postprocess_final()` update: persist images, normalize paths, promote figure captions
- `PipelineResult.image_count` field
- Unit tests for all new functionality

### Out of Scope

- Equation region detection and crops (Item 3 — uses collector infrastructure built here)
- OCR integration (Item 4 — independent)
- Orphan image tracking or reporting (silent orphans are acceptable)
- Changes to Claude prompts or Claude output validation
- New table detectors or GMFT/Img2Table configuration changes
- Table text deduplication on GMFT_APPEND pages (handled by Phase 2 routing fix)

### Edge Cases & Considerations

- **Claude-replaced pages**: pymupdf4llm image references for those pages are lost (Claude produces text, not image refs). The extracted figure files remain on disk as orphans. This is acceptable — orphan images are harmless disk artifacts.
- **Table crops from temp dirs**: Temp files may be cleaned up by the OS. The collector MUST copy (not move) images during `persist()` to avoid race conditions, and SHOULD tolerate missing source files gracefully.
- **No images in document**: Some PDFs have no embedded figures and no detected tables. The collector MUST handle zero entries without error. The `images/` directory MAY be empty or not created.
- **Backward compatibility**: When `extracted_images_dir` is None, behavior MUST be identical to current pipeline (no images, no directory creation, no path normalization).

## Requirements

### Functional Requirements

> Requirements below are from the epic and user's request unless marked [INFERRED].

1. **FR-1**: The pipeline MUST support an `ImageCollector` that accumulates image entries from multiple pipeline steps and persists them to a single output directory.

2. **FR-2**: `ImageCollector.add()` MUST accept a source path, relative output name, image kind (figure/table_crop/equation_crop), and page number. It MUST return the markdown reference string (`![](images/rel_name)`).

3. **FR-3**: `ImageCollector.persist()` MUST copy all registered source files to the output directory and return the count of successfully persisted images. Missing source files SHOULD be skipped with a warning, not raise an error.

4. **FR-4**: `extract_pages()` MUST accept an optional `extracted_images_dir` parameter. When provided, it MUST pass `write_images=True` and `image_path=str(extracted_images_dir)` to pymupdf4llm's `to_markdown()`. When not provided, behavior MUST be unchanged (`write_images=False`).

5. **FR-5**: After table detection and enhancement (step 3b), the pipeline MUST register each `DetectedTable.image_path` (when not None) with the collector. Table crop images MUST be named `page_{NNN}_table_{M}.png`.

6. **FR-6**: `PipelineConfig` MUST have an `extracted_images_dir: Path | None` field (default None). This is distinct from the existing `page_image_dir` (pre-rendered page PNGs for Claude vision).

7. **FR-7**: The CLI (`cmd_extract()`) MUST create `output_dir/images/` and pass it as `extracted_images_dir` in `PipelineConfig`.

8. **FR-8**: `_postprocess_final()` MUST call `normalize_image_paths()` to convert absolute pymupdf paths to relative `images/` paths when `extracted_images_dir` is provided.

9. **FR-9**: `_postprocess_final()` MUST call `promote_figure_captions()` to move figure captions from separate paragraphs into image alt-text.

10. **FR-10**: `PipelineResult` MUST include an `image_count: int` field reflecting the total number of image files in the output images directory (includes both pymupdf-written figures and collector-persisted table crops).

11. **FR-11**: [INFERRED] Table crop markdown references (`![Table N](images/page_NNN_table_M.png)`) SHOULD be inserted near the corresponding pipe table in the merged output, not at the end of the page.

### Non-Functional Requirements

- Backward compatibility: pipeline with `extracted_images_dir=None` MUST produce identical output to current behavior
- No new external dependencies
- Existing tests MUST continue to pass
- Image persistence MUST NOT significantly impact pipeline runtime (file copies, not re-encoding)
